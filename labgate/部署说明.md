# labgate 部署说明（实施人员用）

采集网关以 Docker 容器方式运行。**镜像由研发出好，实施人员不需要编译、不需要源码**，
在线从阿里云仓库拉，离线用镜像包导入。

需要准备的东西只有三样：

| | 说明 |
|---|---|
| Docker Desktop | 客户电脑上预装好（离线环境提前下好安装包） |
| `docker-compose.yml` | 研发提供，直接用，不用改 |
| `.env` | 由 `.env.example` 复制后按现场情况改，**每台机器不一样** |

`docker-compose.yml` 和 `.env` 放在同一个目录下，后面所有命令都在这个目录里执行。

---

## 第一步：配置 .env（两种部署都要做）

复制模板：

```bash
cp .env.example .env
```

Windows 上没有 `cp` 就手工复制一份，改名成 `.env`（注意是 `.env`，前面有个点，没有扩展名）。

### 必改的四项

| 变量 | 填什么 |
|---|---|
| `LABGATE_VERSION` | 镜像版本号，**必须和实际镜像的 tag 一致**（如 `1.0.0`），研发交付时会告诉你 |
| `LABGATE_LIMS_URL` | LIMS 地址，如 `http://192.168.1.18:8081/lims` |
| `LABGATE_LIMS_TOKEN` | LIMS「中转站」模板上登记的 `agent_token`，**一个中转站一个，不能复用** |
| `LABGATE_ADMIN_PASSWORD` | 管理界面登录密码，一客户一密码，不要用模板里的 `change-me` |

### 按需要改的

| 变量 | 什么时候改 |
|---|---|
| `LABGATE_SITE_ID` | 一个实验室一个标识，多实验室时务必区分开 |
| `LABGATE_PORT` | 界面端口，默认 8090；客户机上 8090 被别的程序占了才改 |
| `LABGATE_HOST_LAN_IP` | 天平 / 串口网关就装在这台电脑上时，填这台电脑的局域网 IP |
| `LABGATE_ADMIN_USER` | 登录账号，默认 `admin`，一般不用改 |

其余项保持默认即可。

> `.env` 里有密码和令牌，**不要发到群里、不要提交到代码仓库**。

---

## 第二步 A：本地运行（有网，从阿里云仓库拉）

登录镜像仓库（每台机器只需登录一次，账号问研发要）：

```bash
docker login crpi-z99l88o2fu3lae8l.cn-hangzhou.personal.cr.aliyuncs.com
```

拉取并启动：

```bash
docker compose pull && docker compose up -d
```

---

## 第二步 B：部署到客户电脑（离线，拷贝镜像包）

**① 在有网的机器上导出镜像**（研发做，或实施人员出发前做，文件约 19MB）：

```bash
docker save -o labgate-1.0.0.tar crpi-z99l88o2fu3lae8l.cn-hangzhou.personal.cr.aliyuncs.com/maitux/labgate:1.0.0
```

**② 拷到客户电脑**，U 盘拷这三个文件到同一目录：

```
labgate-1.0.0.tar
docker-compose.yml
.env                    ← 已按上面第一步改好
```

**③ 在客户电脑上导入并启动**：

```bash
docker load -i labgate-1.0.0.tar && docker compose up -d
```

整个过程不需要联网。

---

## 第三步：验证

浏览器打开 `http://localhost:8090`（改过 `LABGATE_PORT` 就用改后的端口），
应该看到登录页 —— 用 `admin` 和 `.env` 里设的密码登录。

命令行确认：

```bash
docker compose ps
```

`STATUS` 列显示 `Up ... (healthy)` 就正常。看日志：

```bash
docker compose logs -f
```

### LIMS 侧配置

在 LIMS 的「中转站」里，`agent_api_url` 填 **这台采集电脑的局域网 IP + 端口**：

```
http://192.168.1.100:8090
```

不要填 `localhost` —— LIMS 在另一台服务器上，`localhost` 指的是 LIMS 自己。

## 日常运维

| 要做的事 | 命令 |
|---|---|
| 看日志 | `docker compose logs -f` |
| 看最近 100 行 | `docker compose logs --tail 100` |
| 重启 | `docker compose restart` |
| 停止 | `docker compose stop` |
| 启动 | `docker compose up -d` |
| 改完 `.env` 生效 | `docker compose up -d`（不是 `restart`） |

### 升级到新版本

1. 研发给新的 tar 包（或告知新版本号）
2. 改 `.env` 里的 `LABGATE_VERSION`
3. 离线：`docker load -i labgate-新版本.tar`；在线：`docker compose pull`
4. `docker compose up -d`

配置和历史数据存在 Docker 数据卷 `labgate-data` 里，升级不会丢。

## 常见问题

**报 `failed to read dockerfile: open Dockerfile: no such file or directory`**

不是缺文件，是**没找到镜像**。九成是 `.env` 里的 `LABGATE_VERSION` 和实际镜像 tag 对不上。
用下面的命令看本机到底有哪些镜像，把 tag 抄进 `.env`：

```bash
docker images crpi-z99l88o2fu3lae8l.cn-hangzhou.personal.cr.aliyuncs.com/maitux/labgate
```

在线部署时也可能是没执行 `docker login`。

**报 `required variable LABGATE_ADMIN_PASSWORD is missing a value`**（或其它 `LABGATE_` 开头的变量）

`.env` 文件没建，或者不在执行命令的当前目录下，或者文件名错了（比如被存成了 `.env.txt`）。

**界面打不开**

检查 `docker compose ps` 是不是 `Up`；再检查客户电脑防火墙有没有放行 8090 端口。

**LIMS 点「开始采集」没反应**

检查 LIMS 里的 `agent_api_url` 填的是不是这台电脑的**局域网 IP**，以及 LIMS 服务器能不能 ping 通这台电脑。

**在界面上改了配置，重启后又变回去了**

正常。`.env` 里设过的项（LIMS 地址、令牌、密码、站点标识等）每次启动都以 `.env` 为准。
要永久改，改 `.env` 再 `docker compose up -d`。

**忘记管理界面密码**

改 `.env` 里的 `LABGATE_ADMIN_PASSWORD`，然后 `docker compose up -d`。
改完所有人的登录状态会立即失效，需要重新登录。

## 容器里有什么、数据在哪

- 镜像里只有程序本身，**不含任何配置**
- `config.json` 是容器**第一次启动时自动生成**的，不用手工准备、也不用拷贝
- 配置和采集数据都在 Docker 数据卷 `labgate-data` 里，`docker compose down` 不会删，
  **`docker compose down -v` 会连数据一起删掉，慎用**
